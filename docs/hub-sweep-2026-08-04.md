# Hub sweep, 2026-08-04: 1,185 unvetted public model files

The benign corpus is curated, which is what makes its false-positive number
defensible and what blinds it. This sweep is the complementary measurement:
no diversity vetting, no cherry-picking, every model-ish file from the repo
trees cached by `scripts/build_benign_manifest.py` that HuggingFace's own
scanning called safe or caution, under 15 MB, round-robin across repos.

## Method

```
python scripts/hub_sweep.py --max-files 1500 --max-size 15000000
```

- Sample: 1,205 of 6,428 eligible files, spread across 495 repos
  (round-robin, largest-first within a repo).
- Downloaded 1,185 (20 download failures), SHA-256 verified against the LFS
  oid where present.
- Scanned with `open-rowan scan --no-sca --no-taint --no-cross-file`, JSON
  report per file. open-rowan at commit cf3b49b (pre-sweep-fixes) for the
  first pass; the two FP classes below were fixed and re-measured at the
  same commit they landed in.
- Full per-file results: `docs/hub-sweep-2026-08-04.json` (verbatim output
  of the run; 17 flagged, 0 scan errors).

This sample did NOT get the corpus's manual vetting, so a flag is not
automatically a false positive: four of the repos below are literally
published scanner-bypass PoCs.

## Results: 17 of 1,185 flagged above INFO

### Real false positives (9 files, 2 classes, both fixed)

1. **MFV-PICKLE-006 read resolved global references as free text** (7
   files). `collections.defaultdict` handed a class reference
   (`builtins.int`, `collections.OrderedDict`) in LightGBM joblib dumps and
   Keras tokenizer pickles. The ref renders as a string, and the
   string-argument check treated it as free text. Fixed by marking
   GLOBAL/STACK_GLOBAL products with `_PickleGlobalRef` so arg-text
   extraction skips them. Files: AC7989/all-mpnet-sbert-lightgbm-disneyland,
   DJF-on-arm/Iamam1 tokenizer.pkl, Sudheer17/sentiment_lstm tokenizer.pkl,
   arjitMathur/imdb-sentiment-models tokenizer.pickle,
   kmposkid1/Horse-Health-Outcome LightGBM pkl, lvizcaya/forex-eurusd
   lgb_model.joblib, redr1g/final-thesis-experiments lightgbm joblib.
2. **MFV-ONNX-002 matched protobuf junk containing ".."** (2 files).
   Quantized weight bytes decode as printable strings that contain two dots
   and a slash by chance (onnx-community/mobilenetv4 model_quantized.onnx,
   model_uint8.onnx). The whole-file check now requires a path shape
   (leading `../` or a `/../` segment).

### True detections (8 files, kept)

- **Rammadaeus/tflite-flex-bypass-poc** (4 fuzz files): MFV-TFLITE-001, the
  rule added the same day, caught root-offset-out-of-bounds shapes.
- **vellaveto/joblib-scanner-bypass-poc** safetensors_overlapping_offsets:
  MFV-ST-006 (overlapping tensor offsets).
- **hacnho/sklearn-dump-svmlight-scanner-bypass-poc**: MFV-PICKLE-005
  (svmlight dump with a filesystem path argument).
- **ScanMe/test-models/traversal.onnx**: MFV-ONNX-002, a deliberate
  external_data traversal test model.
- **julien-c/git-theta-safetensors** model.safetensors: MFV-ST-002, not a
  real safetensors file (git-theta pointer content under a model name);
  header size field is garbage. Correct to flag.

## What this changes about the claims

- The 0/219 corpus number survived contact with an unvetted sample 5x its
  size, but only after two real FP classes were found and fixed. Quoting
  0/219 without the sweep would have been the confident-wrong-number failure
  mode this project exists to avoid.
- A sweep that finds bypass-PoC repos and detects all of them is also
  detection evidence, not just FP evidence.
- The sweep is cheap to re-run and should be repeated on every release
  candidate; the cache (gitignored) makes re-runs download only what is new.
